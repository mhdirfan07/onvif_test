Two Different Camera Paths

Dua Jalur Kamera yang Berbeda

Kamera Bawaan (Camera2)

Built-in Camera (Camera2)

Jalur standar Android: CameraCaptureController minta CameraManager buka sensor kamera, arahkan hasilnya ke Surface milik encoder. Simpel, selalu didukung.

The standard Android path: CameraCaptureController asks CameraManager to open the sensor, pointing its output at the encoder's Surface. Simple, always supported.

Kamera USB (UVC Webcam)

USB Camera (UVC Webcam)

Kasus khusus — kamera USB tak muncul di Camera2 API kebanyakan HP. Solusi: bicara langsung ke USB pakai protokol UVC lewat library org.uvccamera: USBMonitor minta izin, UVCCamera buka koneksi & atur resolusi, lalu gambar digambar ke Surface yang sama.

A special case — USB cameras don't show up in Camera2 on most phones. The fix: talk directly to USB via the UVC protocol using the org.uvccamera library: USBMonitor requests access, UVCCamera opens the connection & sets resolution, then frames are drawn to the same Surface.

The UVC Challenge

Kesulitan yang Ditemukan di Kamera USB

Masalah · Problem

Banyak webcam USB cuma dukung resolusi tinggi (1280×720) dalam format MJPEG (terkompresi), bukan YUYV (mentah) yang jadi default library.

Many USB webcams only support high resolution (1280×720) in MJPEG (compressed), not the raw YUYV format the library defaults to.

Kalau format diminta tak didukung, startPreview() "sukses" tapi tak pernah kirim gambar — Blue Iris terus-menerus connect-disconnect.

If the requested format isn't supported, startPreview() "succeeds" but never actually delivers frames — Blue Iris keeps connecting and disconnecting.

Solusi · Solution

Kode sekarang mencoba beberapa kombinasi resolusi + format secara berurutan — MJPEG dulu, lalu YUYV, lalu ukuran default — sampai salah satu diterima kamera.

The code now tries several resolution + format combinations in order — MJPEG first, then YUYV, then the default size — until the camera accepts one.

#Langkah (ID)Step (EN)

2Client hitung MD5(username:realm:password), gabung dengan method+URL+nonce, di-hash lagi jadi "response".The client computes MD5(username:realm:password), combines it with method+URL+nonce, and hashes it again into a "response".
3Server hitung ulang hash yang sama, bandingkan. Password asli tak pernah melewati jaringan.The server recomputes the same hash and compares. The real password never crosses the network.

RTSP (RFC 2326) pakai skema Digest yang persis sama dengan HTTP — satu class ini otomatis berlaku untuk RTSP juga.

RTSP (RFC 2326) uses the exact same Digest scheme as HTTP — this one class automatically works for RTSP too.

Bug Fixes

Kenapa Restart Server Kadang Bermasalah

EADDRINUSE (Port Bentrok)

EADDRINUSE (Port Conflict)

Stop lalu langsung start lagi — port lama kadang belum benar-benar dilepas OS.

Stop then immediately start again — the old port sometimes isn't released by the OS yet.

Fix: socket RTSP pakai SO_REUSEADDR.

Fix: the RTSP socket now uses SO_REUSEADDR.

Kamera USB Gagal Dibuka

USB Camera Fails to Open

start() dipanggil sebelum proses "tutup kamera" sebelumnya selesai — dua proses rebutan akses ke device USB yang sama (result=-99).

start() was called before the previous "close camera" finished — two processes fighting over the same USB device (result=-99).

Fix: start() menunggu teardown selesai, di thread terpisah.

Fix: start() waits for teardown to finish, on a separate thread.
